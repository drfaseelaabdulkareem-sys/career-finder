# Non-Clinical Career Finder

A paid, device-locked career assessment for healthcare graduates in India who
are exploring non-clinical roles. Runs on Netlify's free tier. No database to
manage, no payment integration, no email service.

**→ Non-technical setup: [SETUP.md](./SETUP.md)**

---

## How access works

Access is sold on the landing page and delivered by hand over Instagram DM.
There is no payment webhook and no transactional email — deliberately, because
both were failure points that could leave a paying buyer locked out.

```
owner replies to a post comment with the site link → buyer presses START →
the access panel shows the Razorpay link and the login box → buyer pays and
DMs the screenshot → owner copies the next unused login out of /api/admin
and pastes it into the chat → buyer signs in on the same page
```

A login is an id plus a passphrase (`CF-K7M2` / `harbour-lantern-48`),
pre-generated in batches. Each one admits **1 device** and lasts **30 days
from first sign-in** — the clock starts when the buyer actually arrives, not
when they paid. Refused device attempts are counted, so the owner can see
which logins are being shared.

Both numbers are stamped onto a login record when it is generated, not read at
sign-in time, so raising `MAX_DEVICES` or `ACCESS_DAYS` never retroactively
changes what an existing buyer was sold.

Login passphrases are stored in plain text on purpose. They are
machine-generated, single-purpose and worth ₹499, and the owner needs to be
able to look one up and resend it over WhatsApp. Hashing them would make the
support path impossible for a non-technical operator.

## Layout

```
src/                       ← ships to the browser. Contains NO worksheet content.
  config.js                ← public settings (Razorpay link, Instagram handle, price)
  lib/api.js               ← device id, session handling, API calls
  components/
    Gate.jsx               ← landing page: access panel (pay + login) and FAQ
    Assessment.jsx  Transition.jsx  Results.jsx
    VortexArt.jsx  Confetti.jsx

netlify/
  lib/                     ← server only. Never downloadable.
    questions.mjs          ← question bank, sanitiser, rehydrator
    roles.mjs              ← 12 role profiles, weights, roadmaps, result copy
    market.mjs             ← salary bands, degree access, city and hiring reality
    scoring.mjs            ← per-dimension normalisation + per-role z-score fit
    calibration.mjs        ← generated by scripts/calibrate.mjs — do not hand-edit
    access.mjs             ← pure access rules (who gets in, expiry, device cap)
    store.mjs              ← Netlify Blobs I/O for logins and devices
    jwt.mjs                ← minimal HS256 sessions (no auth library)
    auth.mjs  http.mjs
  functions/
    login.mjs              ← POST /api/login — id + password + device id
    content.mjs            ← questions with all scoring data stripped
    score.mjs              ← runs the engine, returns matches with no scores
    admin.mjs              ← password-protected login list and batch generator

scripts/
  test-all.mjs             ← scoring, sessions, access rules, device cap, expiry
  verify-build.mjs         ← fails if IP or secrets leak into dist/
  calibrate.mjs            ← re-simulates 40,000 respondents, rewrites calibration.mjs
  set-business-details.mjs ← rewrites the policy pages from src/config.js
```

## Why the content is server-side

`src/` contains the UI and nothing else. The client receives questions with
every scoring field stripped, and sends back only option **ids**. Role
profiles, weights, salary data, roadmaps and result copy never enter the
browser bundle, so the worksheet cannot be downloaded and resold — which is
the actual piracy risk, not the password.

## Before every deploy

```bash
npm test                      # scoring, access rules, no-leak canaries
npm run build && npm run verify
```

`verify` scans the built bundle for role profiles, roadmaps, scoring
internals and secrets, and exits non-zero if it finds any. Point it at any
directory: `node scripts/verify-build.mjs src`.

## Settings

Five environment variables, all server-side. Never prefix one with `VITE_` —
that publishes it. See `.env.example`.

| Variable | Purpose |
|---|---|
| `APP_URL` | the live site, no trailing slash |
| `SESSION_SECRET` | signs buyer sessions and the admin cookie |
| `ADMIN_PASSWORD` | guards `/api/admin` |
| `ACCESS_DAYS` | 30 — counted from first sign-in |
| `MAX_DEVICES` | 1 |

Rotating `SESSION_SECRET` signs every buyer out. Logins themselves survive,
because they live in Netlify Blobs, not in the token.

## Re-calibrating the scoring

`scripts/calibrate.mjs` simulates 40,000 random respondents, measures each
role's raw-score mean and standard deviation, and writes
`netlify/lib/calibration.mjs`. Run it after any change to the question bank,
role weights or dimension set, or the fit comparison across roles drifts:

```bash
node scripts/calibrate.mjs && npm test
```
